# Verigate

## Give AI agents access. Keep control of what they can do.

AI agents can send payments, use business tools and change systems. But when an agent is tricked or makes a mistake, broad permissions can turn one bad answer into a real action. Prompt instructions alone cannot prevent that.

**Verigate checks an action before it happens.** A team sets the limits: what an agent can do, where it can act and when a person must approve. Verigate checks each request independently of the AI. If it is allowed, Verigate creates a one-time signed permission for that exact action. Change the request, exceed a limit or try to reuse the permission, and execution is rejected.

That lets companies automate sensitive work without giving an AI a blank cheque. It also creates proof of what the agent was allowed to do — proof that can be checked independently.

**Built:** an open-source authorization protocol, execution controls, runnable demos and an offline proof verifier. Anna is the first app integration, with natural-language payment interpretation, deterministic policy decisions and a one-time authorization flow. Base/Ethereum wallet hand-off is implemented in the source and covered by automated E2E tests; live wallet connection has not been verified.

**Evidence:** 603 Python unittest cases and 63/63 Anna UI E2E tests passed; contract E2E, strict Anna schema-4 validation and Linux Executa build/smoke also passed in [GitHub Actions CI](https://github.com/rudimentall1/verigate/actions/runs/42786256350). Anna App 0.1.28 is still Draft; source candidate 0.1.29 is in the repository but has not been uploaded. Live Anna Runtime recordings show ALLOW, BLOCK and WARN decisions with verified Decision Receipts. The user deliberately cancelled the in-App permission confirmation; no wallet was connected, and no live ExecutionRouter consumption or on-chain payment is claimed.
