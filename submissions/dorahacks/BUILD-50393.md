# Verigate

## Let AI agents act. Keep control of what they can do.

AI agents are moving beyond chat. They can send payments, call business tools and change live systems. Give an agent broad access and one bad instruction — or one compromised tool — can cause a real loss. Asking the model to follow rules is not enough. The model should not be responsible for enforcing its own limits.

**Verigate is an independent permission layer for AI agents.** Before a sensitive action runs, Verigate checks it against rules set by the owner: what the agent may do, what it may access or spend, and which actions need approval.

When an action is allowed, Verigate issues a signed, one-time permission tied to that exact action. The execution layer checks the permission before carrying it out. Change the details, exceed the rules or try to use the permission twice, and the action is rejected.

Verigate also creates proof that can be checked independently. A team can see not just what an agent did, but what it was authorized to do — without relying on the model's word.

**Who needs it:** teams building AI agents that handle payments, business APIs or other sensitive operations. Verigate lets them give agents useful access without handing over unlimited authority.

**What exists today:** an open-source authorization protocol, working execution controls, runnable end-to-end demos and an offline proof verifier. Anna is the first app integration, demonstrating a USDC payment hand-off path for Base and Ethereum while keeping signing in the user's wallet.

**Test results:** 626 Python tests passed (4 skipped); 61/61 Anna UI end-to-end tests passed.

**Current status:** Anna App 0.1.28 is Draft, not publicly released. Runtime testing reached the MetaMask confirmation screen, but the test was cancelled before signing. No on-chain payment is claimed.
