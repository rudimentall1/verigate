# Verigate

## AI agents should be able to act. They should never decide their own authority.

An AI agent can send a payment, call a tool or change a system. That is what makes it useful — and what makes it risky. A wrong instruction or a manipulated model can trigger an action nobody intended. Asking an AI to be careful is not a security control.

**Verigate is an independent permission layer between an AI agent and the actions it can take.**

You define what the agent is allowed to do and set the limits. The agent proposes an action; Verigate checks it outside the AI model. If it passes, Verigate issues a signed, one-time permission for that exact action. The execution layer checks the permission before carrying it out. Change the action, exceed the rules or try to use the permission again, and it is rejected.

Verigate also creates proof that can be checked independently — so a team can verify what was authorized without simply trusting the AI or the system that ran it.

**Why it matters:** teams can automate real work without handing an AI unlimited authority. They keep control over what an agent can do, while getting evidence of what happened.

**Working today:** an open-source authorization engine, execution controls and an offline proof verifier, with runnable end-to-end demos. Anna is the first payment integration, demonstrating a USDC wallet hand-off path for Base and Ethereum.
